# Модуль AI-агента

Модуль `app/agent` содержит интеграцию GigaChat и инструменты доступа к
служебной логике проекта.

## Файлы

- `giga_auth.py` — получение и кэширование OAuth-токена GigaChat.
- `giga_client.py` — асинхронные HTTP-запросы к GigaChat.
- `schemas.py` — Pydantic-схемы запросов агента, ответов инструментов и
  финального ответа.
- `tools.py` — агентские tools. Каждый tool переиспользует сервисный слой,
  а не обращается к базе данных напрямую.
- `agent_service.py` — orchestration GigaChat: отправка запроса, обработка
  `tool_calls`, вызов tools и формирование итогового ответа.
- `router.py` — REST-endpoint `POST /agent/query` с проверкой JWT-пользователя.
- `authorization.py` — резерв для беззависимых проверок прав агента
  относительно рабочего пространства.
- `confirmation.py` — резерв для Human-in-the-loop подтверждения операций
  создания, изменения и удаления.
- `__init__.py` — пакет модуля.

## Текущий MVP

Сейчас агент поддерживает следующие операции:

```text
list_my_workplaces
update_workplace
```

`list_my_workplaces` получает активные рабочие точки текущего пользователя через
`WorkplaceServices.get_all_by_user()`. Результат ограничен точками владения
пользователя и точками, где он является активным сотрудником.

`update_workplace` только подготавливает изменение и возвращает запрос на
подтверждение; фактическое изменение выполняется через `/agent/confirm`.
Вопросы, не связанные с календарем смен, отклоняются. Календарные запросы,
для которых пока нет tool (например, получение информации о сотруднике),
не обрабатываются автоматически: агент сообщает о необходимости ручного
обращения и перечисляет доступные операции.

Запрос выполняется через:

```text
POST /agent/query
Authorization: Bearer <access_token>

{"query": "Какие у меня рабочие точки?"}
```

Изменяющие действия выполняются только после явного подтверждения:

1. `/agent/query` возвращает `confirmation_required`, `confirmation_id`,
   и точное `confirmation_summary`.
2. Пользователь подтверждает или отменяет действие через
   `POST /agent/confirm` с тем же `confirmation_id`.
3. Подтверждение привязано к пользователю и действует 10 минут.

Для подтверждения изменения владелец или администратор должен иметь права
на указанную рабочую точку. Само изменение выполняется только endpoint
`/agent/confirm`.
