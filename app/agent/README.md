# Модуль AI-агента

Модуль `app/agent` содержит интеграцию GigaChat и инструменты доступа к
служебной логике проекта. Агент отвечает на вопросы о рабочих точках и
календаре смен, используя данные авторизованного пользователя.

## Настройка

Для запуска добавьте в `.env` ключ авторизации GigaChat:

```env
GIGA_API_KEY=<ваш_token>
```
Его можно получить [тут](https://developers.sber.ru/studio/workspaces)

Без ключа запросы к агенту не будут обработаны.

## Файлы

- `giga_auth.py` — получение и кэширование OAuth-токена GigaChat.
- `giga_client.py` — асинхронные HTTP-запросы к GigaChat.
- `schemas.py` — Pydantic-схемы запросов агента, ответов инструментов и
  финального ответа.
- `tools.py` — агентские tools. Каждый tool переиспользует сервисный слой,
  а не обращается к базе данных напрямую.
- `agent_service.py` — orchestration GigaChat: отправка запроса, обработка
  `tool_calls`, вызов tools и формирование итогового ответа.
- `router.py` — REST-endpoints `POST /agent/query` и `POST /agent/confirm`
  с проверкой JWT-пользователя.
- `authorization.py` — проверки доступа пользователя к рабочим точкам и сменам.
- `confirmation.py` — Подтверждения действий на изменение/удаление объектов (Human-in-the-loop).
- `__init__.py` — пакет модуля.

## Возможности

Агент поддерживает следующие операции:

```text
list_my_workplaces
lookup_employee_by_full_name
lookup_employee_by_phone
get_employee_shifts
get_workplace_shifts
update_workplace
create_shift_schedule
```

- **Рабочие точки.** `list_my_workplaces` возвращает активные точки, которыми
  пользователь владеет или в которых он является активным сотрудником.
- **Поиск сотрудника.** Поиск по ФИО (включая часть имени) или телефону
  выполняется среди активных сотрудников точки, где пользователь может
  управлять сменами. Если управляемых точек несколько, пользователь должен
  выбрать нужную; при нескольких совпадениях по сотруднику агент попросит
  уточнение.
- **Просмотр смен.** Сотрудник может просматривать собственные смены.
  Владелец или администратор может просматривать смены сотрудника своей точки,
  а также график всех сотрудников точки. Если период не задан, показываются
  ближайшие 30 дней, включая сегодня. Для одного сотрудника допустим период до
  90 дней, для всей точки — до 30 дней; границы периода включаются.
- **Подготовка графика.** Владелец или администратор может подготовить смены
  для одного активного сотрудника своей точки. Цикл задаётся как количество
  рабочих и выходных дней, например `5/2`, `2/2` или `7/0`, начиная с
  сегодняшнего рабочего дня; период — от 1 до 90 календарных дней. Время можно
  указать парой `start_time` и `end_time`, иначе используются часы точки.
  Даты, уже занятые сменами, пропускаются. Если цикл отсутствует или
  некорректен, подготавливается одна смена на сегодня.
- **Изменение рабочей точки.** `update_workplace` готовит изменение; применить
  его можно только после подтверждения. Создание и удаление рабочей точки
  через агента пока недоступны.

Вопросы вне темы рабочих точек и календаря смен отклоняются. Для операций,
которых нет в списке возможностей, агент сообщает, что их нужно выполнить
вручную.

## API

Оба endpoint требуют JWT-аутентификацию. Текст запроса обязателен, после
обрезания пробелов его длина должна быть от 1 до 500 символов.

Отправка запроса:

```text
POST /agent/query
Authorization: Bearer <JWT>
Content-Type: application/json

{"query": "Покажи мои рабочие точки"}
```

Пример запроса на просмотр смен:

```json
{
  "query": "Покажи ближайшие 5 смен Петра"
}
```
Пример ответа:
```json 
{
  "answer": "Вот ближайшие пять смен Петра:\n\n1. 27 ноября, начало в 09:00.\n2. 28 ноября, начало в 09:00.\n3. 29 ноября, начало в 09:00.\n4. 30 ноября, начало в 09:00.\n5. 3 декабря, начало в 09:00. \n\nВсе смены работают по графику с 09:00 до 21:00."
}
```


При подготовленном действии (изменение/удаление/создание смен), требующем подтверждение от пользователя (Human-in-the-loop), ответ `/agent/query` содержит
`confirmation_required: true`, `confirmation_id` и точное описание
`confirmation_summary`. Покажите план пользователю и передайте его решение в
`/agent/confirm`:

```text
POST /agent/confirm
Authorization: Bearer <JWT>
Content-Type: application/json

{"confirmation_id": "<confirmation_id>", "approved": true}
```

`approved: true` подтверждает действие, `false` отменяет. Подтверждение
привязано к создавшему его пользователю, одноразовое и действует 10 минут.
При выполнении права проверяются повторно. Ответ содержит статус:
`executed`, `cancelled`, `expired` или `invalid`.

За один запрос агента можно подготовить не более одного действия, требующего
подтверждения.

За один запрос нельзя выполнить несколько действий:
```json
{
"query": "Создай сотрудникам Петру и Ивану (+70000000001) смены, у Петра график 2/2 на 14 дней, Ивану 5/2 на месяц"
}
```
