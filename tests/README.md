# Запуск тестов

Тесты покрывают реализованные роутеры:

- `POST /auth/login` — вход (форма `username` + `password`, в ответе `access_token`, `refresh_token`, `token_type`)
- `/users` — `GET /users/me`, `PUT /users/me`, `PUT /users/me/password`
- `/workplaces` — создание, список, карточка, изменение, удаление и `GET /{id}/employees`
- `/employees` — создание и восстановление, карточка, изменение, мягкое удаление
- `/shifts` — создание, карточка, список за дату, календарь, изменение, удаление одной смены и смен даты, размножение

Каталог `app/` тесты только импортируют. Своя схема создаётся в временном файле SQLite, рабочая PostgreSQL не нужна и не изменяется.

## 1. Окружение проекта

Из корня репозитория, как в основном README:

```powershell
uv sync
```

Тестам дополнительно нужны `pytest`, `pytest-asyncio` и `aiosqlite`. Их можно поставить разово, не записывая в `pyproject.toml`:

```powershell
uv run --with pytest --with pytest-asyncio --with aiosqlite pytest --rootdir=. -c tests/pytest.ini tests
```

Та же команда и запускает тесты.

## 2. Если `uv` не установлен

Поставьте зависимости из `pyproject.toml` в виртуальное окружение, затем тестовые пакеты. Запускать pytest нужно из корня репозитория.

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install "fastapi[standard]" "sqlalchemy>=2.1.4" "asyncpg>=0.32.0" "greenlet>=3.5.6" "pwdlib[argon2]" "pydantic-settings" "pyjwt" "email-validator" "python-multipart"
pip install pytest pytest-asyncio aiosqlite
pytest --rootdir=. -c tests/pytest.ini tests
```

## 3. Отдельные файлы

```powershell
pytest --rootdir=. -c tests/pytest.ini tests/test_login.py
pytest --rootdir=. -c tests/pytest.ini tests/test_users.py
pytest --rootdir=. -c tests/pytest.ini tests/test_workplaces.py
pytest --rootdir=. -c tests/pytest.ini tests/test_employees.py
pytest --rootdir=. -c tests/pytest.ini tests/test_shifts.py
```

## Что проверяется

- успешный вход и содержимое JWT (`sub`, `id`, `token_type`, срок refresh длиннее access);
- отказ при неверном пароле, неизвестном email, неактивном пользователе, пустом пароле и входе по телефону;
- логин принимает form-data (`username` — это email), JSON с полем `email` отклоняется;
- профиль `/users/me` без токена, с битым, просроченным и refresh-токеном;
- частичное обновление профиля, телефон `8XXXXXXXXXX`, пустое тело, смена email и пароля;
- точка создаётся от имени текущего пользователя;
- дубликат адреса и типа у того же владельца, повтор после удаления, другой тип и другой владелец;
- список точек: владелец, активный сотрудник, неактивный сотрудник, чужие точки;
- чтение карточки владельцем, сотрудником и админом; чужой пользователь и несуществующий id получают 403;
- изменение и удаление доступны только владельцу (админ точки тоже получает 403);
- удаление мягкое: точка, сотрудники, смены и шаблоны становятся неактивными, повторное удаление — 404;
- список сотрудников точки не включает неактивных и закрыт для посторонних;
- сотрудник ищется по телефону `+7XXXXXXXXXX` или `8XXXXXXXXXX`; в ответе вложенный профиль без email и пароля, дата найма — сегодня, должность необязательна;
- создавать, менять и деактивировать сотрудника могут владелец точки и активный admin; читать — владелец и любой активный сотрудник;
- роль `owner` в карточке сотрудника не даёт прав управления; запись `admin` даёт, пока роль не понижена;
- неизвестный или неактивный пользователь и неактивная точка — 404, повторно активный сотрудник — 409;
- после деактивации тот же телефон восстанавливает ту же запись: роль, должность и дата найма перезаписываются, пустая должность сбрасывается;
- один пользователь может состоять в двух точках; чужая точка, неактивная запись и неизвестный id — 404, посторонний — 403;
- удаление сотрудника мягкое, повторное — 404, его смены остаются активными;
- смена создаётся владельцем или admin со статусом `planned`; время в формате `H:MM` или `HH:MM`, минуты кратны 30, конец строго позже начала; `workplace_id=0` отклоняется проверкой прав, а не схемой;
- в смене сохраняются только сотрудник, дата, время и заметка; статус, дата и сотрудник через изменение времени не переписываются;
- читать смену, день и календарь могут владелец и сотрудники точки; в ответе есть ФИО, нет `status`;
- чтение несуществующей или уже удалённой смены не доходит до ответа 404: `result.one()` бросает `NoResultFound`. Изменение и удаление той же смены отвечают 404;
- пустой день и пустой календарь — 404, период календаря включительный и сгруппирован по дате;
- неактивный сотрудник, сотрудник другой точки и неизвестный id не получают новую смену;
- смена деактивированного сотрудника остаётся читаемой, пока сама смена активна;
- удаление одной смены и всех смен даты мягкое и не затрагивает другую дату или другую точку; повторное удаление — 404;
- размножение строит декартово произведение смен и дат, копирует время, заметки и сотрудника, период ответа — минимальная и максимальная из переданных дат;
- неизвестная, чужая или уже удалённая смена в размножении — 404, новые строки при этом не создаются; пустые списки — 422.
