# Репозиторий backend-server "Календарь смен"

## Быстрый старт с uv

Инструкция по развертыванию окружения и установке всех зависимостей проекта.

### 1. Установка uv (если еще не установлен)

* macOS:

> brew install uv

* Linux:

> curl -LsSf https://astral.sh/uv/install.sh | sh

* Windows (PowerShell):

> winget install astral-sh.uv

**На Linux / Windows может отличаться**

**После установки перезайдите по нужде в терминал и проверить установку командой:**

> uv --version

---

### 2. Активация окружения (вход)

Откройте терминал в корне проекта и выполните команду для вашей ОС:

* macOS / Linux (Bash/Zsh):

> source .venv/bin/activate

* Windows (PowerShell):

> .venv\Scripts\Activate.ps1

* Windows (Командная строка CMD):

> .venv\Scripts\activate.bat

---

### 3. Установка всех библиотек

После активации окружения скачайте и синхронизируйте все зависимости проекта одной командой:

> uv sync

### 4. Запуск сервера 

После настройки можно запустить сервер командой:

> uv run uvicorn app.main:app --reload --port <необходимый порт>

## Добавление библиотеки

Для добавление библиотеки в окружение используйте команду:

> uv add <название библиотеки>

---

## Альтернатива без входа

Если вы можете не активировать окружение вручную, то запустите команду ниже и автоматически применит нужное окружение и библиотеки: 

> uv run uvicorn app.main:app --reload --port <необходимый порт>

---

## Переменные окружения (.env)

Для локального запуска проекта создавать файл .env не обязательно. Все конфигурационные параметры (подключение к базе данных PostgreSQL, настройки CORS и параметры JWT) уже зашиты в коде как значения по умолчанию.

Если вам необходимо изменить стандартные настройки под свою локальную машину, создайте файл .env в корневом каталоге и переопределите нужные переменные:

```
POSTGRES_USER=my_db_user
POSTGRES_PASSWORD=my_secure_password
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
POSTGRES_DB=my_database_name

CORS_ORIGINS=["http://localhost:3000","http://localhost:3001"]

SECRET_KEY=123456789
JWT_ALG=algorithm
```

## Запуск базы данных и сервера

### Шаг 1: Сборка слепка и запуск контейнеров
Каждый раз, когда вы вносите изменения в код или создаете новые файлы миграций, вам необходимо обновлять **слепок (образ) сервера**, так как контейнер изолирован и не видит файлы на вашем компьютере напрямую. 

Для сборки свежего слепка и запуска всей инфраструктуры в фоновом режиме (флаг `-d`), выполните команду в терминале проекта:
```bash
docker compose up --build -d
```
*Docker Compose автоматически проверит ваш `Dockerfile`, заберет актуальный код бэкенда, новые файлы миграций Alembic и создаст обновленный образ.*

### Шаг 2: Контроль готовности и просмотр логов
В вашем `docker-compose.yaml` настроена автоматическая проверка здоровья базы данных (`healthcheck`). Бэкенд не начнет запускаться, пока PostgreSQL полностью не инициализируется. 

Чтобы увидеть, как база проходит проверку, как скрипт `entrypoint.sh` автоматически применяет миграции и как стартует сервер Uvicorn, откройте логи:
```bash
docker compose logs -f
```
*Флаг `-f` (follow) оставляет логи открытыми в реальном времени. Вы увидите строки `Применение миграций Alembic...`, а затем успешный старт: `Uvicorn running on http://0.0.0`. Чтобы выйти из режима просмотра логов, нажмите `CTRL + C`.*

---

### Важное примечание: Порядок работы с миграциями Alembic

Поскольку вы работаете через фиксированные слепки кода, ваш повседневный цикл изменения структуры базы данных выглядит следующим образом:

1. **Создание файла миграции (на компьютере):** Вы меняете модели данных в коде и генерируете новый файл скрипта в локальном терминале проекта:
   ```bash
   uv run alembic revision --autogenerate -m "описание_изменений"
   ```
2. **Перенос миграции в слепок:** Файл создался на ПК, но контейнер о нем еще не знает. Выполните команду из Шага 1 (`docker compose up --build -d`), чтобы пересобрать слепок сервера вместе с новым файлом миграции.
3. **Автоматическое применение:** При старте обновленного бэкенда скрипт `entrypoint.sh` внутри контейнера сам обнаружит новый файл и автоматически применит команду `alembic upgrade head` к базе данных PostgreSQL. Вам больше не нужно вводить команды применения руками.
