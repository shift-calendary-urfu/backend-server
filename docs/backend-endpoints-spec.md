# Спецификация API-эндпоинтов для 1 спринта

## Общая информация

- **Base URL:** `/api/v1`
- **Аутентификация:** JWT Bearer Token (кроме `/auth/*`)
- **Формат данных:** JSON
- **Версионирование:** через URL (`/api/v1/...`)

---

## Роутер 1: `auth` (Аутентификация)

**Префикс:** `/api/v1/auth`

| Метод | Путь | Описание | Request | Response | Auth |
|-------|------|----------|---------|----------|:----:|
| POST | `/register` | Регистрация нового пользователя | `email`, `password`, `phone`, `first_name`, `second_name`, `third_name` (опц.) | `{id, email, phone, first_name, second_name, ...}` | ❌ |
| POST | `/login` | Вход в систему, получение JWT | `email`, `password` | `{access_token, token_type}` | ❌ |
| POST | `/logout` | Выход из системы (опционально, можно просто удалить токен на клиенте) | — | `{message: "Logged out"}` | ✅ |

**Примечания:**
- При регистрации создаётся только `User`, без привязки к точкам
- `phone` — обязательное поле (подготовка под будущее SMS-подтверждение)
- `is_phone_verified = False` устанавливается автоматически при регистрации
- `access_token` имеет срок жизни (например, 30 минут)
- SMS-шлюз пока не подключён — заглушка на будущее. Когда будет готов, добавятся:
  - `POST /auth/send-code` — отправка SMS-кода на `phone`
  - `POST /auth/verify-code` — подтверждение кода
  - `POST /auth/login-by-phone` — вход по телефону + SMS-код

## Роутер 2: `users` (Профиль пользователя)

**Префикс:** `/api/v1/users`

| Метод | Путь | Описание | Request | Response | Auth | Роли |
|-------|------|----------|---------|----------|:----:|------|
| GET | `/me` | Получить текущего пользователя | — | `{id, email, phone, first_name, second_name, third_name, is_phone_verified}` | ✅ | Все |
| PUT | `/me` | Обновить профиль текущего пользователя | `first_name`, `second_name`, `third_name`, `phone`, `email` (все опц.) | Обновлённый пользователь | ✅ | Все |
| PUT | `/me/password` | Изменить пароль | `old_password`, `new_password` | `{message: "Password updated"}` | ✅ | Все |

**Примечания:**
- `/me` — стандартный паттерн для получения данных текущего пользователя
- В ответе добавлены `phone` и `is_phone_verified`
- При смене `phone` поле `is_phone_verified` сбрасывается в `False`
- `email` можно изменить через `PUT /me`, но это редкая операция — подтверждение через ссылку можно добавить позже
- Пароль меняется только после проверки старого пароля

## Роутер 3: `workplaces` (Рабочие точки / ПВЗ)

**Префикс:** `/api/v1/workplaces`

| Метод | Путь | Описание | Request | Response | Auth | Роли |
|-------|------|----------|---------|----------|:----:|------|
| GET | `/` | Получить список точек текущего пользователя (где он owner или employee) | — | `[{id, name, address, workplace_type, work_start_time, work_end_time, owner_id, ...}]` | ✅ | Все |
| GET | `/{workplace_id}` | Получить детальную информацию о точке | — | `{id, name, address, phone, description, workplace_type, work_start_time, work_end_time, owner_id, ...}` | ✅ | Owner/Admin/Employee точки |
| POST | `/` | Создать новую рабочую точку | `name`, `address`, `phone` (опц.), `description` (опц.), `workplace_type`, `work_start_time`, `work_end_time` | Созданная точка | ✅ | Все (автоматически становится owner) |
| PUT | `/{workplace_id}` | Обновить рабочую точку | `name`, `address`, `phone`, `description`, `workplace_type`, `work_start_time`, `work_end_time` (все опц.) | Обновлённая точка | ✅ | Owner/Admin точки |
| DELETE | `/{workplace_id}` | Удалить рабочую точку | — | `{message: "Workplace deleted"}` | ✅ | Только Owner |
| GET | `/{workplace_id}/employees` | Получить список сотрудников точки | `is_active` (опц., фильтр) | `[{id, user_id, role_in_workplace, position, ...}]` | ✅ | Owner/Admin/Employee точки |

**Примечания:**
- `address` — обязательное поле (для ПВЗ критично)
- `workplace_type` принимает значения: `ozon`, `wildberries`, `yandex_market`, `other`
- `work_start_time`, `work_end_time` — рабочие часы ПВЗ (например, `09:00` и `21:00`), используются при расчёте отчётности
- При создании точки пользователь автоматически становится `owner` (через `Workplace.owner_id`)
- `DELETE` — только owner (подтверждено заказчиком). Каскадное удаление или soft delete — **нужно обсудить с командой**
- `PUT` — owner и admin (подтверждено заказчиком)
- Фильтр `is_active` для сотрудников — чтобы показать только активных

## Роутер 4: `employees` (Сотрудники)

**Префикс:** `/api/v1/employees`

| Метод | Путь | Описание | Request | Response | Auth | Роли |
|-------|------|----------|---------|----------|:----:|------|
| POST | `/` | Добавить сотрудника в точку | `user_id` (ID существующего пользователя), `workplace_id`, `role_in_workplace`, `position` (опц.), `hire_date` (опц.) | Созданный профиль сотрудника | ✅ | Owner/Admin точки |
| GET | `/{employee_id}` | Получить информацию о сотруднике | — | `{id, user_id, workplace_id, role_in_workplace, position, is_active, ...}` | ✅ | Owner/Admin/Employee точки |
| PUT | `/{employee_id}` | Обновить информацию о сотруднике | `role_in_workplace`, `position`, `hire_date`, `is_active` (все опц.) | Обновлённый профиль | ✅ | Owner/Admin точки |
| DELETE | `/{employee_id}` | Деактивировать сотрудника (soft delete) | — | `{message: "Employee removed"}` | ✅ | Owner/Admin точки |
| GET | `/me/workplaces` | Получить список точек, где текущий пользователь является сотрудником | — | `[{id, workplace_id, role_in_workplace, ...}]` | ✅ | Все |

**Примечания:**
- При добавлении сотрудника нужно проверить, что `user_id` существует и не является уже сотрудником в этой точке (UNIQUE constraint)
- `DELETE` — **soft delete** (устанавливаем `is_active = False`), чтобы сохранить историю смен (подтверждено заказчиком)
- При деактивации нужно проверить: нет ли у сотрудника будущих смен. Если есть — предупредить или запретить
- `/me/workplaces` — полезно для переключения между точками в интерфейсе

## Роутер 5: `shifts` (Смены)

**Префикс:** `/api/v1/shifts`

| Метод | Путь | Описание | Request | Response | Auth | Роли |
|-------|------|----------|---------|----------|:----:|------|
| GET | `/` | Получить список смен с фильтрами | `workplace_id` (опц.), `employee_id` (опц.), `date_from` (опц.), `date_to` (опц.), `status` (опц.) | `[{id, workplace_id, employee_id, date, start_time, end_time, status, ...}]` | ✅ | Owner/Admin/Employee точки |
| GET | `/{shift_id}` | Получить детальную информацию о смене | — | `{id, workplace_id, employee_id, date, start_time, end_time, status, notes, ...}` | ✅ | Owner/Admin/Employee точки |
| POST | `/` | Создать новую смену | `workplace_id`, `employee_id`, `date`, `start_time`, `end_time`, `notes` (опц.) | Созданная смена | ✅ | Owner/Admin точки |
| PUT | `/{shift_id}` | Обновить смену | `employee_id`, `date`, `start_time`, `end_time`, `status`, `notes` (все опц.) | Обновлённая смена | ✅ | Owner/Admin точки |
| DELETE | `/{shift_id}` | Удалить смену | — | `{message: "Shift deleted"}` | ✅ | Owner/Admin точки |
| POST | `/bulk` | Массовое создание смен (для размножения) | `[{workplace_id, employee_id, date, start_time, end_time}, ...]` | `{created: [...], errors: [...]}` | ✅ | Owner/Admin точки |
| GET | `/calendar` | Получить смены для календаря (по точке и периоду) | `workplace_id`, `date_from`, `date_to` | `{dates: {"2026-10-15": [{employee_id, start_time, end_time}, ...]}}` | ✅ | Owner/Admin/Employee точки |
| GET | `/check-availability` | Проверить, доступен ли сотрудник в указанное время | `employee_id`, `date`, `start_time`, `end_time` | `{available: true/false, conflicts: [...]}` | ✅ | Owner/Admin точки |

**Примечания:**
- Статусы смен: только `planned` и `cancelled` (план = факт, отдельного хранения факта нет)
- Валидация шага времени: `start_time` и `end_time` должны быть с шагом 30 или 60 минут (валидируется в Pydantic-схемах)
- Фильтры в `GET /` — для гибкого поиска (по точке, сотруднику, периоду, статусу)
- `POST /bulk` — для быстрого создания нескольких смен сразу (например, при размножении)
- `GET /calendar` — специальный эндпоинт для календаря, возвращает данные в удобном для фронтенда формате (группировка по датам)
- `GET /check-availability` — проверка пересечений смен перед созданием

**Бизнес-логика при создании смены:**
1. Проверить, что сотрудник активен в точке (`is_active = True`)
2. Проверить, что у сотрудника нет пересечений с другими сменами (в этой или других точках)
3. Проверить, что `start_time < end_time` (или `end_time < start_time` для смен через полночь)
4. Проверить шаг времени (30/60 минут)

## Роутер 6: `shift_templates` (Шаблоны для автоформирования)

**Префикс:** `/api/v1/shift_templates`

| Метод | Путь | Описание | Request | Response | Auth | Роли |
|-------|------|----------|---------|----------|:----:|------|
| GET | `/` | Получить список шаблонов | `workplace_id` (опц.), `employee_id` (опц.), `is_active` (опц.) | `[{id, workplace_id, employee_id, work_pattern, ...}]` | ✅ | Owner/Admin точки |
| GET | `/{template_id}` | Получить детальную информацию о шаблоне | — | `{id, workplace_id, employee_id, work_pattern, shift_duration_hours, default_start_time, cycle_start_date, ...}` | ✅ | Owner/Admin/Employee точки |
| POST | `/` | Создать новый шаблон | `workplace_id`, `employee_id`, `work_pattern`, `shift_duration_hours`, `default_start_time`, `cycle_start_date` | Созданный шаблон | ✅ | Owner/Admin точки |
| PUT | `/{template_id}` | Обновить шаблон | `work_pattern`, `shift_duration_hours`, `default_start_time`, `cycle_start_date`, `is_active` (все опц.) | Обновлённый шаблон | ✅ | Owner/Admin точки |
| DELETE | `/{template_id}` | Удалить шаблон | — | `{message: "Template deleted"}` | ✅ | Owner/Admin точки |
| POST | `/generate` | Сгенерировать смены на основе шаблона | `template_id`, `date_from`, `date_to` | `{generated_shifts: [...], conflicts: [...]}` | ✅ | Owner/Admin точки |

**Примечания:**
- `POST /generate` — **ключевой эндпоинт для Приоритета 2** (автоматическое формирование графика)
- Алгоритм генерации:
  1. Берём `cycle_start_date` как точку отсчёта
  2. Применяем `work_pattern` (например, 2/2 = 2 дня работы, 2 выходных)
  3. Для каждого рабочего дня ставим смену с `default_start_time` и длительностью `shift_duration_hours`
  4. Проверяем конфликты с существующими сменами
  5. Возвращаем список созданных смен и список конфликтов
- **Важно:** нужно обсудить с командой, как обрабатывать конфликты (пересечения смен)

## Роутер 7: `reports` (Отчётность)

**Префикс:** `/api/v1/reports`

| Метод | Путь | Описание | Request | Response | Auth | Роли |
|-------|------|----------|---------|----------|:----:|------|
| GET | `/workplace/{workplace_id}` | Отчёт по точке за месяц | `month` (формат: `2026-10`) | `{workplace: {...}, period: "2026-10", employees: [{employee_id, full_name, shifts_count, hours_worked, hours_planned}, ...]}` | ✅ | Owner/Admin точки |
| GET | `/employee/{employee_id}` | Отчёт по сотруднику за месяц | `month` (формат: `2026-10`) | `{employee: {...}, workplace: {...}, period: "2026-10", shifts_count, hours_worked, hours_planned, shifts: [...]}` | ✅ | Owner/Admin/Employee (только свой) |

**Примечания:**
- Отчётность в MVP — только вывод на экран, без выгрузок в Excel/PDF
- Расчёт строится по актуальному графику (план = факт, таблица `Shift`). Если админ изменил график — отчёт пересчитывается автоматически
- Шаг расчёта: 30 или 60 минут (валидируется при создании смен)

**Логика расчёта часов:**
- Если смена сотрудника совпадает с рабочими часами ПВЗ (`work_start_time` — `work_end_time`) → 1 полная смена
- Если смена меньше графика ПВЗ → считаем фактические часы (`end_time - start_time`)
- Если смена больше графика ПВЗ → 1 полная смена + доп. часы

**Пример:** ПВЗ работает 09:00–21:00 (12 часов)
- Сотрудник 10:00–18:00 → 8 часов
- Сотрудник 09:00–21:00 → 12 часов (полная смена)
- Сотрудник 08:00–22:00 → 14 часов (12 + 2 доп.)
